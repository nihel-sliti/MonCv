Compression et pruning : CSV contre ParquetCompression and pruning: CSV versus Parquet

Le column pruning s'applique aussi au CSV : le parser ne matérialise que les colonnes du select (défaut depuis Spark 2.4) — le fichier est parcouru en entier, mais les colonnes inutiles ne sont jamais parsées. Sur Parquet, elles ne sont même pas lues sur disque. Deux pièges de vocabulaire : file compression (non, la compression Parquet est interne au format) contre data compression (oui, snappy par défaut) ; et inferSchema coûte une passe de lecture complète.Column pruning applies to CSV too: the parser materialises only the select's columns (default since Spark 2.4) — the file is scanned in full, but unneeded columns are never parsed. On Parquet they are not even read from disk. Two vocabulary traps: file compression (no, Parquet's compression is internal to the format) versus data compression (yes, snappy by default); and inferSchema costs a whole extra read pass.
